# Single-prompt engineering execution

Spec ID: **SPEC-ENG-PROMPT-001** | Version: **2.0.0** | Effective: **2026-11-09**

A business request triggers a complete scoped engineering loop using maintained repository knowledge. The user should not repeat folder layouts, standards, prior corrections, branding or handover rules.

1. Resolve the exact project and inspect current requirements, instructions, Git state and evidence.
2. Select applicable capabilities and task recipes. Reuse existing components and verified commands.
3. Create/update the current OpenSpec change with acceptance scenarios, impact and verification plan.
4. Implement with living comments and relevant product/security/UX requirements.
5. Run real affected checks, diagnose failures and fix them; retain honest blocker states for missing external prerequisites.
6. Synchronize affected specifications, user/developer guides, PDF outputs and document inventory.
7. Review, scan, reconcile intended governance, commit stable work and push when authorized and available. Deploy only within requested scope and declared environment identity.
8. Record results and the next action so a new session resumes without rediscovery.

This version supersedes the blanket execution defaults in version 1.0.0 under [ADR-0029](../decisions/ADR-0029-versioned-engineering-governance.md). The full contract is [SPEC-ENG-GOV-001](engineering-governance-spec.md). Specialized product/device/release acceptance requirements remain applicable.

The control-plane recipes and tooling list support UI/UX, code quality, CMS, calculation engines, data, workflows, mobile and release work. A deterministic plan is preparation: it does not execute arbitrary prompt text or prove implementation/test success. A named unregistered project remains blocked pending exact identity instead of being routed to another client.
